Chapter 1. What data mining is, and how it fails

Data Mining as Observation, draft 0.3, 2026-09-09. Week 1 of ECE 514. No reading is due before this chapter. TSK chapter 1 is due before the second session [1]. Every number below traces to a committed file listed in the last section.

Three engineers, in three different buildings, are about to make the same mistake.

The first has compressed the memory of a language model to the lowest reconstruction error her team has ever recorded, and the model has quietly gotten worse. The second has a new compressor for the vector index behind a legal-search product. It shrinks the index by more than half with almost no change in average vector fidelity, and the product's citation ranking has fallen off a cliff for reasons his dashboards cannot locate. The third works on a microphone array that estimates where a sound came from. Her codec compresses the recordings with beautiful waveform fidelity, and her estimator now points a few degrees wrong, consistently, in a way that averages to nothing and so hides in every summary statistic she trusts.

None of the three has a bug. Each has a compressor that does exactly what it was asked to do, minimize the difference between the input and its reconstruction, and each has a downstream system that does not care about that difference. The model's attention reads a few directions of the compressed memory. The ranking function reads a projection of the embeddings. The estimator reads the angle of the recordings and not their loudness. In every case the compressor spread its error to be small on average, which is to say it put error everywhere, which is to say it put error exactly where the consumer was looking. They optimized a quantity that was never the one that mattered, and they optimized it well.

This book is about the quantity that mattered. The rest of this chapter says what data mining is, states the one idea the book adds to the standard account, and shows that the four ways a data-mining project fails are four ways of losing track of that idea.

1.1 Data mining is a task, and a task names a decision

TSK defines data mining as the process of discovering useful patterns in large data, and organizes it around tasks. Predictive tasks learn a function from known attributes to an attribute of interest. Classification when the target is a category, regression when it is a number. Descriptive tasks summarize the data itself. Association analysis finds attributes that co-occur. Clustering finds groups of rows that resemble each other. Anomaly detection finds rows that resemble nothing. The modern additions, ranking, retrieval, recommendation, and generation, are these four tasks composed and scaled, and chapter 11 treats the ones this course needs.

The session deck adds one word to that definition, and the book is built on it. A task is not a technique. It is a decision. The same business question, which customers will leave, is a classification task if the decision is whom to call, an uplift task if the decision is whom the call will change, and a survival task if the decision is when to call. The label, the metric, and the model all follow from the decision, and a project that cannot name its decision cannot name any of them.

The framing workshop on Wednesday takes three candidate datasets from the class and translates each, live, from question to task to label to decision threshold. Do that translation for your own candidate before you arrive. It is the first exercise at the end of the chapter, and it is the exercise the whole term repeats.

1.2 The one idea this book adds

Every data-mining method produces something that is read by something else. A classifier's scores are read by a threshold and a person. A cluster assignment is read by a marketing rule. A compressed embedding is read by a ranking function. A summary statistic is read by a decision maker. The book calls the thing that reads the consumer, and its single claim is this.

The quality of a representation, a distance, a reduction, an index, or an evaluation is not a property of the object. It is a property of the relation between the object and the consumer that reads it, under a budget. Until the consumer and the budget are named, the question "how good is this" has no answer. Not a hard answer. No answer, the way "how far away is it" has no answer until you say from where.

The book packages the consumer with two more things and calls the package an observer. The three parts are introduced here in words. Section 0.5 of the toolkit gives the arithmetic.

$$O=(C,\ G,\ B). \tag{1.1}$$

That the same read operator is not the same observer, since reversing the sign of every sensitivity reverses every ranking and leaves the operator unchanged, is machine-checked in Lean in appendix C.

  • The consumer is the computation that reads the representation. A classifier, a ranker, an attention head, an estimator, a decision rule. It is, deliberately, whatever is downstream.
  • The output metric is how the consumer's mistakes are scored. Accuracy, precision at a threshold, rank correlation, angular error, dollars lost. It is where "what counts as a mistake" is written down, and section 8.2 shows what happens when it is written down wrong. The book writes it as $G$ in the triple. Where the metric has a local quadratic representation at the consumer's output, the same letter names that local geometry in equation 0.11. A dataset-level loss has no such geometry, and for it the read operator is taken on the score with the identity geometry.
  • The budget is the resolution the consumer may spend. Bits per row, embedding dimension, folds, seconds, dollars. Every verdict in the book is relative to a budget, and chapter 4 shows a verdict reversing when the budget changes.

An observer, once named, tells you two things. It tells you which directions of the data the consumer can distinguish, which the book calls the read subspace, and which directions it is blind to, which the book calls the nuisance. A consumer that reads a customer's purchase history and ignores their postcode has the postcode in its nuisance. A consumer that reads the angle between two vectors and ignores their lengths has length in its nuisance. Section 0.5 shows that both of those facts are computable from the consumer alone, by perturbing its input and watching its output, and section 0.6 shows that collapsing the nuisance to a point is what the word quotient means.

That negating a consumer keeps its read operator and reverses every comparison, and that two cost matrices give the same two classifiers opposite verdicts, are machine-checked in Lean in appendix C.

Two consumers with the same read operator on the same workload share the same local read geometry, and every allocation and distortion the book computes from that geometry is the same for both. They are not thereby the same observer. The consumer $x$ and the consumer $-x$ have the same read operator, workload, output metric, and budget and reverse every ranking, which is why the consumer stays a part of the triple. Nor is the same read subspace alone enough for the geometry. The identity and the diagonal that weights one direction a hundred times the other share a read subspace and a nuisance, and they allocate differently. What a language model's attention and a seismometer array turn out to share is a read geometry, and chapter 4 shows the same phenomenon in both.

1.3 The four failure modes are four missing elements

The session deck names four ways a data-mining project fails [11]. The label is bad. The evaluation lies. The model does not survive deployment. There was no decision. The standard account treats these as four separate hazards with four separate checklists. The book's account is that they are one hazard. Each is an element of the observer left unnamed.

No decision is the case with no consumer at all. A model was built because the data was available, and nothing reads its output. The observation program records this as a precondition rather than a result. Every claim in the book requires a working consumer, and with no consumer there is nothing to be right or wrong about. A project with no decision cannot fail, which is the same as saying it cannot succeed, and the field guide's decision test at the end of this chapter exists to catch it in week one rather than week fifteen.

A bad label is a wrong output metric. The label is where "what counts as a mistake" is written down, and a label that records who was contacted rather than who would have responded, or who was diagnosed rather than who was ill, scores the consumer's mistakes against the wrong target. The model can be optimal for the label and useless for the decision. Chapter 8 shows a metric that read lossless while the consumer read ruined, and the label is the same failure one step earlier.

A lying evaluation is the case where the evaluation harness is itself a consumer, with its own read subspace, and that subspace includes a direction the deployed consumer will never see. The harness reads the test fold's labels through a feature selected on all rows. It reads next month's data through a timestamp. It reads the same customer on both sides of a split. Chapter 8 is entirely about this failure, and its rule is that a number reported by a harness is a number about the harness until the harness's read subspace has been named.

The deployment mismatch is the case where the consumer that was evaluated is not the consumer that was deployed. The model was scored by accuracy and deployed behind a threshold that reads only its top decile. It was scored on a corpus and deployed on a workload whose queries visit different regions. It was evaluated at one budget and served at another. Or it was evaluated at one time and served later, when the world had moved, which chapter 13 calls the certificate that ages. In every case the read subspace changed between evaluation and deployment and nobody measured the change.

The book's claim is not that naming the observer prevents these failures. It is that naming the observer is what makes them visible, and that a project which writes down its consumer, its output metric, and its budget in week one has written down the three things every later chapter checks.

1.4 Reconstruction error is one reader's distortion

The three engineers shared a yardstick, and the yardstick deserves a fair hearing before the book spends twelve chapters arguing against trusting it.

Reconstruction error, the mean squared difference between a thing and its approximation, has three virtues and they are real. It is cheap. You compute it from the input and the output with no knowledge of what happens downstream. It is universal. It gives every compressor, every reduction, every imputation a single comparable score, so methods can be ranked without knowing what anyone will do with the result. And it is theoretically blessed. It is the distortion for which the classical theory of compression has its cleanest closed forms. A generation of engineering was built on it and the buildings are standing.

The three virtues are one vice wearing three coats. Reconstruction error is cheap, universal, and blessed because it names no consumer. It scores the object against its approximation and asks nothing about who reads the result. That is exactly what makes it portable, and exactly what makes it wrong when portability is a lie, when the thing downstream does not read every direction equally.

The precise relationship is one line, and section 0.5 has the arithmetic. The distortion a consumer feels is the error's variance weighted by how much the consumer reads each direction. Total reconstruction error is that quantity for the consumer that reads every direction equally, the identity reader. The two coincide for every error in exactly that one case, and a particular error can make them coincide by accident, which is why the equivalence is quantified over all admissible errors. Reconstruction error is not universal. It is the identity reader's distortion, one member of a family with one member per observer. It became the default because the tools were built for it, and a tool built for one reader makes everything look like that reader.

$$d_O=\operatorname{tr}(P_C\,M_\delta),\qquad \big(d_O=\operatorname{tr}M_\delta\ \text{ for every admissible } M_\delta\big)\ \Longleftrightarrow\ P_C=I. \tag{1.2}$$

When the consumer genuinely reads every direction equally, reconstruction error is not an approximation to the right answer. It is the right answer, and the book has no quarrel with it. The quarrel begins the moment the consumer cares about some directions more than others, which is to say a classifier, a ranker, an attention head, an estimator, a decision rule. Which is to say almost always.

The number the book is named after. The observation program's founding measurement is a compressed attention memory [12, 13] that read cosine similarity 0.995 against the original, all but perfect by the reconstruction yardstick, while the language model's perplexity rose to the order of ten thousand, which section 0.11 explains means the model was broken. Nothing was wrong with either measurement. They measured different things, and only one of them was the thing that shipped. A second measurement made the point in its purest form. A recalibration step improved reconstruction on every window and made the consumer worse on every window. The two numbers disagreed in sign.

Chapter 4 shows that this disagreement is not a curiosity. At matched budget, a code that preserves what the consumer reads beats a reconstruction-optimal code on the consumer's task while reconstructing the data worse. The program sealed that prediction in twelve domains and three branches of physics [13] and it held in at least five independent domains and all three physics. The code that is worse by the universal yardstick is better by the only yardstick that ships.

1.5 What the book claims, and what it does not

A textbook that adds an idea owes the reader the idea's boundaries, and this one carries them from the first chapter.

The boundaries, stated once. The consumer-relative effect needs a consumer whose read subspace is misaligned with where the data has its variance. When the two coincide the effect cannot appear, and chapter 4 has the measured case where it does not. It needs a working consumer, and a project with no decision has none. It is relative to a budget, and a verdict at one budget does not transfer to another. And it says nothing about correlations that no reading of a shared record could produce. Chapter 3 has the sealed audit in which a hubness mechanism that sounded like the book's own reasoning was tested against a physical bound and did not move it [13].

The evidence discipline. Every number in the book was written down as a prediction before it was measured, or is labelled as not having been. Each chapter's headline carries one of six classes, proved, demonstrated, replicated, predicted, exploratory, or refuted, and chapter 8 explains what each requires. A chapter may not rest its thesis on anything below demonstrated. Every number traces, in the table at the end of each chapter, to a committed file with a line number and, where one exists, a permanent identifier. The program's own rule is that it may not assert what its ledger cannot show, and the book inherits it.

What the book does not do. It does not replace TSK or ESL [1, 2]. The standard content of each week stays in those texts and is cited, not rewritten. The book's own pages are the observer reframing of each week's topic, the instruments the reframing produced, and the failure cases that earned it. A reader who wants the derivation of principal components or the proof that boosting converges goes to the standard text. A reader who wants to know which directions the derivation assumed the consumer reads, and what happened when the assumption was wrong, stays here.

1.7 Choosing a dataset

The field guide in the session deck lists where data lives. General archives, government and credentialed sources, and the domain classics by unit. It also gives a test for choosing well, and the test is the observer triple in disguise.

The decision test. What decision will be made differently because of this analysis, and who makes it. A dataset that passes has a consumer. A dataset that fails is a dataset with no decision, the fourth failure mode, and no amount of modelling will supply one.

Label, rows, provenance, license. Is the target recorded as the decision needs it, or as a proxy. That is the output metric. Are there enough rows for the event the decision cares about to occur enough times to be graded. Chapter 8 calls a run with too few events vacuous and gives the bar. Where did the rows come from, and could the collection process have read the label. That is the lying-evaluation mode one step earlier. May you use it, and may you publish what you find.

The red flags. An over-mined toy is a dataset on which every method has already been tuned, so that a good number says nothing about your method. A leakage red flag is any column that could only be known after the decision, or any identifier that appears more than once.

Bring one candidate on Wednesday. The class will name its decision, its consumer, its metric, and its budget in front of you, and the exercise is harder than it sounds.

1.8 What a project proposal must state

The proposal is due in week four and is one page, decision first. It states the following, and every later homework checks the same list.

  • The decision. What will be done differently, by whom, at what threshold.
  • The consumer. The computation or the person that reads the model's output, and what directions of the data it reads.
  • The output metric. How the consumer's mistakes are scored, and why that scoring matches the decision.
  • The budget. Rows, features, bits, seconds, or dollars, whichever binds.
  • The feared failure mode. Which of the four, and what in week one already suggests it.

A proposal that names a technique and not a decision will be returned with this list.

Exercises

Warm-up

  1. State TSK's four canonical tasks and, for each, name a consumer that reads its output.
  2. Explain the difference between a task and a technique, using the churn example.
  3. Write the observer triple for a spam filter. Name what its consumer reads and one thing it discards.
  4. For each of the four failure modes, name the element of the observer that was left unnamed.
  5. Why does the book say a project with no decision cannot fail?
  6. State the three virtues of reconstruction error and the one vice they share.
  7. In what single case is reconstruction error the right distortion, and why is that case rare?
  8. Two consumers have different internals and the same read operator on the same workload. What do they share, what may still differ between them, and what if they shared only the read subspace?
  9. Give an example of a deployment mismatch in which the consumer's read subspace changed between evaluation and deployment without any change to the model.
  10. Which two of the book's fourteen data-mining chapters are labelled standard content with a sidebar, and why does the book say so?

By hand

  1. A consumer reads only the first of three coordinates. Write its read operator as a three by three matrix, and compute the trace of that operator times a covariance with diagonal (1, 4, 9) and no off-diagonal entries. Compute the identity reader's distortion on the same covariance. State the ratio.
  2. Two errors have covariance with diagonals (0.3, 1.7) and (1.7, 0.3). A consumer reads the direction at 15 degrees from the first axis. Using section 0.3, compute the consumer's distortion for each and the ratio.
  3. A churn decision calls the top 5 percent of customers by predicted risk. The model is evaluated by accuracy on all customers, of whom 3 percent churn. Compute the accuracy of a model that predicts no churn for anyone. State which failure mode this evaluation exhibits.
  4. A dataset has 2000 rows and the event the decision cares about occurs in 0.4 percent of them. Compute the number of events. State whether a bar of recall at least 0.9 can be graded, and why.
  5. A retrieval index is evaluated on the corpus's own rows as queries and deployed on a workload that visits 2 percent of the corpus 80 percent of the time. Name the failure mode and the element of the observer that changed.
  6. Classify the following under the four failure modes. A fraud label that records which transactions were investigated. A test set drawn from the same month as the training set for a model deployed next month. A model built on a public dataset because the dataset was available. A feature computed from a field that is filled in after the decision.

Programming

  1. Take one candidate dataset from the field guide. Write its decision, consumer, output metric, and budget in one paragraph each, then run the decision test. If it fails, choose another dataset and repeat.
  2. For the dataset that passed, count the rows in which the event the decision cares about occurs. Compare to the bar you would set for a graded evaluation, following section 8.3.
  3. Build the simplest possible consumer for that dataset, a linear score on standardized features, and estimate its read operator by finite differences at a budget of twice the feature count, following section 0.5. Report which three features it reads most and which three it ignores.
  4. Find a public notebook that models the same dataset. Audit it against the four failure modes and report which, if any, it exhibits, with the line that exhibits it.
  5. Compute reconstruction error and the read distortion of exercise 19's consumer for a reduction of the dataset to half its features by variance. Report both, and state whether they agree about how much was lost.
  6. Write the proposal skeleton of section 1.8 for your dataset. Commit it. The commit hash goes in the week 2 submission and will be compared to the week 4 proposal.

Answers to the warm-up and by-hand problems are collected in the answer key at the end of the book.
